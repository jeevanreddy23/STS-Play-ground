# Learning loop

The vault as a *recursive* learning system, not a filing cabinet. One cycle:

1. **Drill.** Work a flashcard deck below (Obsidian's Spaced Repetition plugin
   reads the `#flashcards/...` tags; on the web viewer, read the deck and
   self-test). Failed cards name the skills to reread.
2. **Study.** Walk the learning path for the weakest area — each path is
   staged observe → measure → calculate → judge, and is meant to be re-entered
   whenever a later stage exposes a gap in an earlier one.
3. **Apply.** Do the field or office work. The skill notes are working aids;
   the source documents stay the authority.
4. **Capture.** When reality differs from a note — a form revision, a step the
   record never showed, a mistake worth remembering — capture it at the moment
   it happens (the viewer's Capture tab, bank *lesson*, or a quick note in
   Obsidian) naming the skill it belongs to.
5. **Refine.** Periodically fold captures back into the skill notes: amend the
   procedure or caveats, bump `updated`, adjust `confidence`. Then regenerate —
   the decks and paths are built *from* the skill notes
   (`gen-learning.py`), so a refined note automatically becomes refined cards.
   The next Drill runs on the improved vault. That closure is the recursion.

Skills whose sources are records rather than procedures (`field-source`) get
better with every pass of this loop — each capture is new evidence.
